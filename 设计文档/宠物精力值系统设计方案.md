# 宠物精力值系统设计方案（修订版）

## 概述

给宠物增加「精力值」系统：用户互动喂养宠物 → 精力上升 → 精神饱满；长时间不互动 → 精力衰减 → 无精打采。精力满时触发跑屏动画——宠物在屏幕上来回跑一圈。纯本地存储，不依赖云函数，不改精灵图资源。

---

## 1. 数据模型

```typescript
// 存储 key: 'petEnergy'
// 存储位置: uni.setStorageSync / uni.getStorageSync

interface PetEnergy {
  score: number           // 0–100，当前精力值
  updatedAt: number       // 最后更新时间戳 (ms)
  lastRunAt: number       // 上次跑屏时间戳 (ms)，用于防重复
  dailyCounts: {          // 当日各类加分计数
    date: string          // 'YYYY-MM-DD'，跨天自动重置
    record: number        // 记录事件次数
    chat: number          // 聊天发送次数
    petting: number       // 抚摸 3 连击次数
    reply: number         // 帮我回复TA 次数
  }
}
```

### 日期工具

```js
function getLocalDateKey(): string
// 返回本地时区的 YYYY-MM-DD，用于日上限计数和跨天重置。
// 不能用 new Date().toISOString().slice(0, 10)，它在 UTC 下切天，
// 中国时区 (UTC+8) 早上 8 点才换日期，日上限体验会错位。
// 实现：new Date().getFullYear() + '-' + pad(month+1) + '-' + pad(date)
```

### 默认值（首次使用）

```js
{
  score: 60,
  updatedAt: Date.now(),
  lastRunAt: 0,
  dailyCounts: { date: getLocalDateKey(), record: 0, chat: 0, petting: 0, reply: 0 }
}
```

|--------|------|-----------|-------------|
| 80–100 | 精神饱满 | `jumping` | "今天状态超好！想记什么？" |
| 50–79 | 正常 | `idle` | "嗯，在呢。今天有什么新发现？" |
| 25–49 | 饿了 | `waiting` | "有点没精神…来陪陪我吧" |

| 场景 | 精灵图 | 持续 | 说明 |
|------|--------|------|------|

## 3. 加分规则

| 行为 | 加分 | 日上限 | 触发位置 |
|------|------|--------|---------|
| 记录事件 | +30 | 3 次/天 | `helpers.ts` `markLastRecordDate()` → 内部调用 `feedPet('record')`；`api.ts` `createTimelineRecord` 成功回调 → 改为 `import { feedPet }` 调用 `feedPet('record')` |
| 聊天发送 (chat) | +15 | 3 次/天 | `PetSpeakSheet.vue` `sendMessage` 成功分支内 |
| 帮我回复TA / 主动开口 | +10 | 3 次/天 | `PetSpeakSheet.vue` `sendMessage` 成功分支内 |
| 抚摸 3 连击 | +10 | 2 次/天 | `index.vue` `onPetTouchEnd` 中 tapCount≥3 分支 |

**上限保护**：同一天内同一行为超过上限不再加分。跨天自动重置计数。

### 记录事件加分特别说明

现有 `lastRecordDate` 有两个写入点，必须全部替换：

| 位置 | 当前代码 | 改为 |
|------|---------|------|
| `src/utils/helpers.ts:350` | `uni.setStorageSync('lastRecordDate', ...)` | 内部调用 `feedPet('record')`，再写 `petEnergy.updatedAt` |
| `src/utils/api.ts:667` | `uni.setStorageSync('lastRecordDate', ...)` | `import { feedPet } from '@/utils/helpers'`，改为 `feedPet('record')` |

实现时建议全局搜索 `lastRecordDate`，确保没有遗漏的写入点。`helpers.ts` 中 `getPetMood()` 对 `lastRecordDate` 的**读取**在改为读 `petEnergy.score` 后即可废弃。

## 4. 衰减规则

- **触发时机**：每次用户打开首页（`index.vue` `onShow`）时调用 `decayPetEnergy()` 计算一次
- **公式**：`elapsed = 当前时间 - updatedAt`；`衰减量 = floor(elapsed / 4小时) × 5`
- **衰减后更新**：`updatedAt = Date.now() - (elapsed % 4小时)`，即保留不足 4 小时的余量，避免下次打开重复扣分
- **下限**：精力值不低于 0
- **示例**：12h 不活跃 → -15，updatedAt 推进 12h；用户 1 分钟后再打开 → elapsed ~1min → 衰减 0
- **示例**：4.5h 不活跃 → -5，余量 0.5h 保留；下次只需再积累 3.5h 就会扣下一个 -5

## 5. 跑屏动画

### 触发条件

精力值达到 **100** 且 `lastRunAt` 距离当前时间 ≥ 30 分钟时触发。

### 防重复机制

```js
function checkAndRunPet(): boolean {
  const energy = readPetEnergy()
  if (energy.score < 100) return false
  if (petIsRunning.value) return false  // 已在跑
  if (Date.now() - energy.lastRunAt < 30 * 60 * 1000) return false  // 30 分钟内跑过
  // 立刻落分值 + 标记，不等动画结束
  energy.score = 85
  energy.lastRunAt = Date.now()
  energy.updatedAt = Date.now()
  writePetEnergy(energy)
  petScore.value = 85
  petIsRunning.value = true
  startRunAnimation()
  return true
}
```

关键：**先落分、先标记、再启动动画**。动画结束只做 UI 恢复，不再操作数据。

### 动画流程

```
1. 精灵图切换为 running-right，隐藏消息气泡，禁用交互
2. viewport 加 .pet-run-right class：translateX 从 -100vw → 100vw（1.5s）
3. 到达右边后，精灵图切换为 running-left
4. viewport 加 .pet-run-left class：translateX 从 100vw → -100vw（1.5s）
5. 回到原位，移除 class，精灵图切回 jumping，恢复气泡和交互
```

### CSS 实现

动画加在 `.pet-sprite-viewport`（外层 wrapper）上，**不加在 `.pet-sprite-sheet`（image）上**。现有精灵图帧定位依赖 `petSpritesheetStyle` 设置的 `transform: translate(-col*cellWidth*scale, -row*cellHeight*scale)`，跑屏动画如果直接覆盖 image 的 transform 会破坏逐帧定位。

```scss
.pet-sprite-viewport.pet-run-right {
  animation: petRunRight 1.5s ease-in-out forwards;
}
.pet-sprite-viewport.pet-run-left {
  animation: petRunLeft 1.5s ease-in-out forwards;
}

@keyframes petRunRight {
  from { transform: translateX(-100vw); }
  to   { transform: translateX(100vw); }
}
@keyframes petRunLeft {
  from { transform: translateX(100vw); }
  to   { transform: translateX(-100vw); }
}
```

### 跑屏期间

- 宠物交互（tap/long-press）暂时禁用：`petIsRunning` 为 true 时 `onPetTouchStart` 直接 return
- 消息气泡隐藏：模板 `v-if="!petIsRunning && petMsg"`
- 精灵图尺寸不变：viewport 的 `width/height/overflow:hidden` 保持，image 内帧定位不受影响

## 9. 实现注意事项

1. **全局搜索 `lastRecordDate`**：实现前 `grep -rn lastRecordDate src/`，确认所有写入点都已替换，所有读取点已迁移或废弃。
2. **跑屏 transform 隔离**：动画 translateX 加在 `.pet-sprite-viewport`，不碰 `.pet-sprite-sheet` 的 transform。
3. **feedPet 时机**：必须在 `res.success === true` 之后，不能在发送开始时调用。Token 不足、网络异常等失败路径不触发加分。
4. **防重复跑屏**：开始动画前立刻写 `score=85 + lastRunAt=now`，不等动画结束。
5. **衰减保留余量**：`decayPetEnergy` 衰减后 `updatedAt = Date.now() - (elapsed % 4h)`，保留不足 4 小时的零头，防止短间隔重复打开时重复扣分。

## 10. 验证方式

1. 新用户精力值 60，宠物 `idle`，泡泡"嗯，在呢。"
2. 记事件 ×2：精力 +60 → 100。触发跑屏（精灵图先 `running-right` 从左侧外跑到右侧外，再 `running-left` 跑回），跑完精力回落 85，精灵图 `jumping`。
3. 抚摸 3 连击：精力 +10，日上限 2 次，第三次不增。
4. 聊天发送成功：精力 +15；失败/Token 不足不计分。
5. 24 小时不活跃：精力 -30，从 85 掉到 55，精灵图从 `jumping` 变为 `idle`。
6. 48 小时不活跃：精力继续衰减，精灵图变为 `failed`，泡泡"我有点没精神，来陪我一下吧"。
