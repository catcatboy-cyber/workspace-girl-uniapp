全系统只用一个用户可见单位："次"。1 次 = 1 次 AI 调用，不论功能。
后端内部用 Token 做成本核算，但永远不暴露给前端用户。

💡 为什么可以"全部统一 1 次"

即时反馈（~1,700 token）和周复盘（~1,670 token）的 API 成本差异不到 ¥0.001。
从成本角度完全没有必要对用户做差异化定价。统一消耗对用户心智友好，后端成本可忽略。
如果未来上线"超深度分析"（如 ¥0.05+ 成本的功能），可以在该功能上标注"消耗 3 次"作为例外。

五、次数消耗逻辑

每次 AI 调用前执行（伪代码）

// 云函数入口处统一调用 checkAndConsumeCall() async function checkAndConsumeCall(db, userId) { const user = await db.collection('users').doc(userId).get() const now = new Date() // 1. 试用期内 → 直接放行 if (user.trialEndsAt && now < user.trialEndsAt) { return { allowed: true, source: 'trial' } } // 2. 无限版 → 直接放行 if (user.plan === 'ultra') { return { allowed: true, source: 'ultra' } } // 3. 月初重置套餐次数 const monthStart = new Date(now.getFullYear(), now.getMonth(), 1) if (!user.monthlyCallsReset || user.monthlyCallsReset < monthStart) { await db.collection('users').doc(userId).update({ monthlyCallsUsed: 0, monthlyCallsReset: monthStart }) user.monthlyCallsUsed = 0 } // 4. 获取当前套餐次数上限 const planConfig = await getSubscriptionConfig() const monthlyLimit = planConfig.plans[user.plan].monthlyCalls // 5. 先扣套餐次数 if (user.monthlyCallsUsed < monthlyLimit) { await db.collection('users').doc(userId).update({ monthlyCallsUsed: user.monthlyCallsUsed + 1 }) return { allowed: true, source: 'monthly', remaining: monthlyLimit - user.monthlyCallsUsed - 1 } } // 6. 套餐用完，扣加油包/奖励次数 if (user.extraCalls > 0) { await db.collection('users').doc(userId).update({ extraCalls: user.extraCalls - 1 }) return { allowed: true, source: 'extra', remaining: user.extraCalls - 1 } } // 7. 全没了 → 拒绝 return { allowed: false, code: 'QUOTA_EXCEEDED', message: '本月次数已用完', actions: [ { type: 'upgrade', label: '升级 Pro（200次/月）' }, { type: 'recharge', label: '买个加油包' } ] } }

消耗优先级

套餐月度次数 → 加油包/奖励次数
先扣每月刷新的套餐次数（不用白不用），套餐次数用完才扣加油包的不过期次数。
这样用户买加油包不会觉得浪费——它永远在套餐用完后再扣。

十一、API 成本（内部核算，用户不可见）

后端追踪实际 Token 消耗，仅用于成本核算，不暴露给用户

基于 v2.0 365 条真实调用数据：
· 每次 AI 调用的 API 成本：¥0.001 ~ ¥0.01（混元 HY）
· 免费用户 20 次/月 → 月成本 ¥0.02 ~ ¥0.20
· Pro 用户 200 次/月 → 月成本 ¥0.20 ~ ¥2.00
· Pro 月费 ¥19，毛利率 90% ~ 99%
token_usage_records 集合持续记录每次调用的实际 token 消耗，用于运营分析和成本监控。
用户侧永远只看到"次数"，不需要知道 token 是什么。
