v3.0 核心设计原则

1. 全参数可配置：试用天数、各 tier 功能配额、定价、加油包、分享奖励 —— 全部在 CloudBase system_settings 中配置，Admin 后台修改即时生效，无需发版。
2. 永久免费版存在：不给付费墙，免费用户永远是蓄水池和传播节点。付费转化靠"高级功能吸引"而非"基础功能切断"。
3. 月度配额自然清零：每月 1 号重置，给用户明确的"新开始"感受，避免永不过期的 Token 囤积。
4. 奶茶定价：锚定大学生/青年群体日常消费心理价位（¥3-39），不做高价。

Admin 后台统一管理，修改后即时生效，云函数每次调用实时读取。

前端展示要点：
- "我"页面新增"邀请好友"卡片，显示剩余邀请次数（本周还能邀请 3/5 人）
- Token 流水（token_ledger_records）新增类型：referral_inviter（邀请奖励-邀请人）、referral_invitee（邀请奖励-被邀请人）

- 邀请人收到服务通知/站内提示："XXX 已加入 Crush Master！你获得了 3,000 Token 🎉"

💡 为什么这个奖励结构对大学生有效

1. 5,000 Token ≈ 3 次即时反馈——被邀请人拿到奖励后立刻能用，不是空洞的"优惠券"。
2. "好友邀请奖励"标签——隐含社交认可（"我朋友在用这个分析她的 crush"），比系统赠送更有温度。
3. 邀请人也赚——学生群体天然有分享动力（宿舍、社团、闺蜜圈），双向奖励让分享没有"拉人头"的负罪感。
4. 3,000 vs 5,000 的不对称设计——被邀请人拿得更多，邀请人不会觉得自己在"收割"朋友，纯粹是"好东西分享给你"。

5.4 未来扩展：邀请排行榜

可选的 gamification 层：每月邀请榜 TOP 10 额外奖励（比如免费 Pro 一个月）。
大学生群体对排行榜+荣誉感的反应极强（参考：微信读书的"读书排行"、多邻国的"连胜"）。
此项为远期规划，不在 v3.0 首期实施范围。

六、月度配额清零机制

每月 1 号 00:00（服务器时间），所有用户的 monthlyQuotaUsed 自动重置为 {}。
实现方式：每次 AI 调用前，云函数检查 user.monthlyQuotaReset 是否早于当月 1 号，若是则清零。

清零逻辑（伪代码）

// 每个 AI 调用云函数的入口处 const now = new Date() const monthStart = new Date(now.getFullYear(), now.getMonth(), 1) if (!user.monthlyQuotaReset || user.monthlyQuotaReset < monthStart) { await db.collection('users').doc(userId).update({ monthlyQuotaUsed: {}, monthlyQuotaReset: monthStart }) } // 然后判断：monthlyQuotaUsed[feature] < planQuota[feature] const used = user.monthlyQuotaUsed?.[feature] || 0 const limit = plan.monthlyQuota[feature] if (limit !== -1 && used >= limit) { return { code: 'QUOTA_EXCEEDED', message: '本月免费次数已用完，升级 Pro 继续使用' } }
