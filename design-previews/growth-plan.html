GROWTH PLAN v1.0

拉新体系完整方案

当前拉新只有"桃花人格卡分享"一个入口，新用户点进来要先建 case、做 14 题。构建多渠道分享拉新体系，核心原则：先给价值，再引导建档

一、基础设施（先做，所有渠道共用）

1.1 静默自动注册

  • App.vue onLaunch 中调 wx.login() → 云函数 login 返回 userId
  • userId 存入 uni.storage，不再弹登录页
  • pages/login/login.vue 保留但不再作为必经路由

1.2 默认 Crush 自动创建

  • 新增 getOrCreateDefaultCase()：如果用户没有任何 case，自动创建 { name: 'TA', profile: {} }
  • 调用时机：首次进入"我们"页面、渠道 2/3/4 落地页需要 Crush 时
  • 创建后页面顶部显示 "编辑画像"提示条

1.3 画像采集改为行内

  • 新建组件 ProfileInline.vue：姓名 + 性别 + 年龄 + 星座 + 生肖，5 个字段，卡片内表单
  • 不跳整页，在半屏弹出或卡片内完成
  • 所有渠道落地页共享此组件

三、关键设计原则

3.0 隐私匿名化（所有渠道强制）

分享卡片和落地页绝对不能暴露分享者的隐私数据

原始数据分享快照中替换为落地页展示
Crush 真实姓名"TA" / "某人"仅展示分析结构
Crush 头像/照片默认占位头像不展示
本人姓名/头像不出现不出现
事件中的具体人名/地名脱敏或截断仅展示摘要趋势
分数/趋势数据保留（这是分享价值）展示结构，数据可模糊
  • 生成分享图时调用 anonymizeData() 清洗
  • 渠道 3 只分享卡片结构 + 趋势形状，不分享具体数字和姓名

3.1 落地页共用组件

ProfileInline本人画像采集
5 字段卡片表单
CrushInlineCrush 画像采集
姓名+性别+照片
LandingFooter底部钩子 CTA
自适应渠道文案
ShareSnapshot卡片快照展示
静态只读

3.2 画像收集策略

渠道收集时机阻断？
渠道 1 桃花人设全部 5 字段是（必须填才有结果）
渠道 2 一句话解读可跳过否（一句话就够了）
渠道 3 我们卡片Crush 名字必须半阻断（名字必填，其余跳过）
渠道 4 桃花匹配2 份画像都必填是（匹配需要双方数据）

3.3 静默登录异常处理

  • wx.login 失败：展示"需要微信授权" + [一键登录] 按钮
  • 后台创建用户失败：展示错误 + [重试] 按钮
  • 正常情况用户完全无感
