# Crush Master v1.2 拉新体系升级 — 开发计划（修订版 v2）

## 背景

v1.1 已实现：静默登录 + 4 条渠道归因 + quickRead 闭环 + 后台转化展示。

**问题：** 奖励靠 `wechatLogin` 里顺手调 `redeemInviteCode`，没有幂等保障、没有漏斗数据、老用户回访无记录。

**v1.2 目标：可统计、可防刷、奖励可追溯。**

---

## 关键原则

| 原则 | 含义 |
|------|------|
| `users.landing*` | 首次注册归因，**永不覆盖** |
| `share_visits` | 每次访问事件，**不参与奖励** |
| `referral_claims` | 唯一邀请关系，**参与奖励** |
| `call_usage_records` | 奖励流水，带 `claimId` |
| `redeemInviteCode` | 只走新 claim/settle，不直接发奖 |
| 旧用户回访 | 只写 visit，不创建 claim，不发奖 |

## 一、数据模型

### 新增集合 1：`share_visits`

每次通过分享链接打开时记录。**不参与奖励。**

| 字段 | 类型 | 说明 |
|------|------|------|
| `shareId` | string | 来自 `appendReferralParams` |
| `channel` | string | `analysis_share` / `taohua_card` / `we_card` / `invite` |
| `scene` | string | 可为空 |
| `inviteCode` | string | 邀请码 |
| `path` | string | 打开时的路径 |
| `visitorUserId` | string | 登录后有值，未登录为空 |
| `openidHash` | string | sha256(openid) 前 16 位 |
| `isNewUser` | boolean | 此次是否创建了新用户 |
| `loginSuccess` | boolean | 是否成功登录 |
| `createdAt` | Date | |

**写入时机：**
1. `onLaunch` → 匿名 visit（openidHash + path，其余空）
2. `wechatLogin` 成功 → 补写 login visit（带 userId/isNewUser）

### 新增集合 2：`referral_claims`

唯一邀请关系 + 奖励状态。

| 字段 | 类型 | 说明 |
|------|------|------|
| `inviteeUserId` | string | 被邀请人（**唯一约束：一个用户只能被邀请一次**） |
| `inviterUserId` | string | 邀请人（**可重复：一个人可以邀请多人**） |
| `inviteCode` | string | 邀请码 |
| `shareId` | string | 关联的分享 ID |
| `channel` | string | 来源渠道 |
| `status` | enum | `rewarded` / `blocked` |
| `inviterTokens` | number | 邀请人实际获得的 Token 数（发放时落盘） |
| `inviteeTokens` | number | 被邀请人实际获得的 Token 数（发放时落盘） |
| `rewardedAt` | Date | 发放时间 |
| `createdAt` | Date | |
| `updatedAt` | Date | |

**奖励金额从 `system_settings.settings_subscription.referral` 读取：**
- `inviterRewardTokens`（默认 3000）
- `inviteeRewardTokens`（默认 5000）

注册时**一次发放双方完整金额并落盘到 claim**。配置后续变更不影响历史记录。

## 二、新增共享模块

### `_shared/referral-settlement.js`

```js
// 注册时调用：创建 claim + 双方发奖
async function settleReward(db, inviteeUserId, inviterUserId, inviteCode, shareId, channel) {
  // 1. 幂等：检查 inviteeUserId 是否已有 claim → 有则返回（一个用户只能被邀请一次）
  // 2. 自邀请：inviterUserId === inviteeUserId → blockClaim
  // 3. 读 config.referral 奖励金额（inviterRewardTokens / inviteeRewardTokens）
  // 4. 创建 claim（status='rewarded', inviterTokens=$inviterRewardTokens, inviteeTokens=$inviteeRewardTokens）
  // 5. 邀请人 +inviterRewardTokens（addExtraTokens → call_usage_records，带 claimId）
  // 6. 被邀请人 +inviteeRewardTokens（同上）
  // 7. 返回 { success, claim }
}

async function blockClaim(db, inviteeUserId, reason) { ... }
```

### `_shared/visit-tracking.js`

```js
async function trackAnonymousVisit(db, { shareId, channel, scene, inviteCode, path, openid }) { ... }
async function trackLoginVisit(db, { shareId, visitorUserId, isNewUser, openid }) { ... }
```

## 三、改动现有云函数

### `wechatLogin/index.js`

1. **登录成功后写 visit：**
   ```js
   const { trackLoginVisit } = require('./_shared/visit-tracking')
   trackLoginVisit(db, { shareId: landingShareId, visitorUserId: user._id, isNewUser, openid })
   ```

2. **新用户注册后结算（替换原 redeemInviteCode 调用）：**
   ```js
   if (isNewUser && inviteCodeParam) {
     const inviter = await db.collection('users')
       .where({ inviteCode: inviteCodeParam }).limit(1).get()
     if (inviter.data.length > 0 && inviter.data[0]._id !== user._id) {
       const { settleReward } = require('./_shared/referral-settlement')
       await settleReward(db, user._id, inviter.data[0]._id,
         inviteCodeParam, landingShareId, landingChannel)
     }
   }
   ```

3. **返回加 `isNewUser`：**
   ```js
   return { ..., isNewUser }
   ```

### `register/index.js`

同 wechatLogin。

### `redeemInviteCode/index.js`

改为走 `settleReward`，不再直接 `addExtraTokens`。
